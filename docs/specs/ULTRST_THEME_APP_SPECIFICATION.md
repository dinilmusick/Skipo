## 0. Executive Summary & Architectural Scope

This specification establishes the authoritative, end-to-end technical standard for the **ULTRST / Skipo Theme Ecosystem** and the **Theme Maker Application (`ThemeApp`)**. 

It reconciles the high-level ULTRST directional architecture (ecosystem identity, per-app user state, decoupled workspace storage, and public/private marketplace lifecycles) with the concrete runtime contracts, AST validation rules, and design token invariants of **Skipo** (`@skipo/core`, `@skipo/ui`, `@skipo/systems`, `@skipo/backend`, and `@skipo/validate`).

### Explicit Scope Reconciliations:
1. **Full Manifest & Runtime Specification (Previously Delegated)**: All manifest schemas, token models, asset mappings, and loader interfaces are fully formalized in this document with production TypeScript schemas.
2. **Deterministic UI Inheritance**: Any theme pack generated by `ThemeApp` is 100% plug-and-play compatible with `<SkipoThemeProvider>` and automatically styles every `@skipo/ui` and `@skipo/systems` component without code modifications.
3. **Multi-Asset Rendering Support**: Supports pure CSS variables, monochromatic SVGs, raster/9-slice tactile textures, and subsystem extensions (e.g., node graphs, code editors).
4. **ThemeApp Architectural Invariants**: `ThemeApp` itself is built as a Skipo Standalone App, strictly obeying Skipo Laws (single `TopToolbar`, flat tabs, dedicated `BottomStrip`, zero floating bubbles, `FloatingDetailsPanel` with 8-way resize/pinning, and zero placeholder data).

## 1. System Data Model & Database Schemas

The ecosystem operates on a strict separation between the **Control Plane** (System Database storing users, preferences, and theme metadata references) and the **Data Plane** (Workspace Storage storing actual theme pack directory trees, CSS files, SVGs, and raster sprites).

```
ULTRST_SYSTEM_DATABASE
├── ULTRST_USERS
│   └── USER (<user_id>)
│       ├── identity & credentials (email, passwordHash, role, displayName)
│       ├── global_data (ecosystem-wide preferences)
│       ├── <APP_ID> (lazily created per-app user object)
│       │   ├── preferences (app-specific layout, active theme reference)
│       │   ├── credentials (app-specific API keys / service endpoints)
│       │   └── workspaces[] (WorkspaceDescriptor: id, name, storage_options)
│       └── THEME_APP
│           ├── preferences (active editor layout, default preview mode, color space, autoSave)
│           ├── credentials (storage provider credentials, S3/B2 keys)
│           ├── workspaces[] (theme workspace storage configurations)
│           └── private_themes[] (THEME_REFERENCE[])
│
└── ULTRST_PUBLIC_THEMES
    └── PUBLIC_THEME_REFERENCE[] (Global marketplace catalog)
```

## 2. Authentication & Ecosystem Identity

Authentication is unified across all applications using `@skipo/backend/auth`.

```
                  USER
                   │
                   ▼
               APP LOGIN
                   │
                   ▼
         ULTRST_SYSTEM_DATABASE
                   │
                   ▼
             ULTRST_USERS
                   │
    ┌──────────────┴──────────────┐
    ▼                             ▼
[User Exists]               [User Absent]
    │                             │
    │                             ▼
    │                        CREATE USER
    │                             │
    └──────────────┬──────────────┘
                   │
                   ▼
       LAZY APP_OBJECT CREATION
       (if USER.<APP_ID> absent)
                   │
                   ▼
           SESSION TOKEN ISSUED
```

### Authentication Invariants:
1. **Single Identity**: One ecosystem username/email and credentials per human operator.
2. **Cross-App Token**: JWT or bearer session token verified by all ecosystem apps via `SessionManager`.
3. **Lazy Namespace Creation**: If an authenticated user launches `ThemeApp` for the first time, the backend automatically initializes `USER.THEME_APP` with default preferences and workspace references without disrupting existing app states.

## 3. Workspace Storage Architecture

Theme files (CSS, JSON, SVGs, PNGs) MUST NOT be stored as base64 or blob records in `ULTRST_SYSTEM_DATABASE`. Instead, they reside in **Workspace Storage** conforming to `@skipo/backend/storage`.

```
USER
└── APP_OBJECT (THEME_APP)
    └── WORKSPACE
        └── STORAGE_OPTIONS
            ├── PRIMARY (e.g. Backblaze B2, Cloudflare R2, AWS S3, or Local Disk)
            ├── BACKUP[] (optional secondary synchronization)
            └── PROVIDER_CONFIG (credentials, bucket, basePath)
```

### Storage Provider Abstraction:
All filesystem operations in `ThemeApp` interface through `BaseStorageAdapter`:
- **`LocalFSAdapter`**: For desktop applications (Electron/Tauri) or browser File System Access API.
- **`S3Adapter`**: For object storage (Backblaze B2, Cloudflare R2, MinIO, AWS S3).
- **`SupabaseStorageAdapter`**: For Supabase bucket storage.

Consuming applications do NOT configure separate storage buckets for themes; they resolve themes directly through the storage provider configuration referenced in `THEME_REFERENCE` or `PUBLIC_THEME_REFERENCE`.

## 6. Private Theme Lifecycle

```
           THEME_APP
               │
               ▼
       1. CREATE THEME PACK
               │
               ▼
       2. VALIDATE PACKAGE (Quality Gate)
               │
               ▼
       3. SAVE TO USER WORKSPACE STORAGE
          (<workspace-root>/THEME_PACKS/<id>/)
               │
               ▼
       4. CREATE THEME_REFERENCE
               │
               ▼
       5. INSERT INTO USER.THEME_APP.private_themes[]
               │
    ┌──────────┴──────────┐
    ▼                     ▼
  APP_A                 APP_B
    │                     │
    ▼                     ▼
READ USER.THEME_APP.private_themes[]
    │                     │
    ▼                     ▼
RESOLVE STORAGE ADAPTER VIA WORKSPACE CONFIG
    │                     │
    ▼                     ▼
LOAD manifest.json + styles.css
    │                     │
    ▼                     ▼
PASS TO <SkipoThemeProvider initialThemePack={...}>
```

### Strict Lifecycle Rules:
1. **Creator-Scoped Discovery**: Private themes are visible only to the owning user across their authenticated applications.
2. **Zero Ingestion Duplication**: Consuming apps (`APP_A`, `APP_B`) MUST NOT copy or duplicate the theme pack into their private databases. They load directly from the creator's theme workspace storage.
3. **Hot Reloading**: Modifying a theme in `ThemeApp` immediately propagates across all running ecosystem apps upon next refresh or via `@skipo/core` event sync.

## 7. Public Marketplace Theme Lifecycle

```
        PRIVATE_THEME
             │
             ▼
      USER CLICKS "PUBLISH"
             │
             ▼
         THEME_APP
             │
             ├── 1. Run Complete Verification Gate (AST + Zero-Placeholder + Contrast)
             │
             ├── 2. Upload Bundle to Canonical Public Storage (S3/B2 Bucket)
             │
             ├── 3. Insert Public Theme Record into ULTRST_PUBLIC_THEMES
             │
             └── 4. Update USER.THEME_APP.private_themes[].isPublic = true
                         │
                         ▼
        CONSUMING APPLICATIONS (ANY AUTHENTICATED USER)
                         │
                         ▼
               READ ULTRST_PUBLIC_THEMES
                         │
                         ▼
             RESOLVE CANONICAL STORAGE URL
                         │
                         ▼
             STREAM THEME PACK INTO UI
```

### Marketplace Rules:
1. **Immutable Semver Releases**: Once published at version `X.Y.Z`, a public theme package is immutable. Edits must publish a subsequent semver.
2. **Canonical CDN Delivery**: Public themes are cached on the ecosystem CDN. No user-specific storage quota is consumed when installing a public theme.
3. **Sandboxed CSS**: Custom CSS in public themes is sanitized to prevent external `@import` or injection vectors.

## 8. Consuming Application Startup & Resolution Protocol

Every Skipo application executes the following startup sequence:

```typescript
// 1. Authenticate user
const session = await authProvider.getSession();

// 2. Load app-specific user state
const appObject = await systemDb.getAppObject(session.userId, APP_ID);

// 3. Load user's private themes
const themeAppObject = await systemDb.getAppObject(session.userId, 'THEME_APP');
const privateThemes: ThemeReference[] = themeAppObject?.private_themes || [];

// 4. Load public themes catalog
const publicThemes: PublicThemeReference[] = await systemDb.getPublicThemes();

// 5. Determine active theme
const activeSelection = appObject.preferences.activeTheme || { source: 'builtin', id: 'skipo-dark-neo' };

let activeThemePack: SkipoThemePack;
if (activeSelection.source === 'builtin') {
  activeThemePack = activeSelection.id === 'skipo-light-coffee' ? DEFAULT_LIGHT_THEME_PACK : DEFAULT_DARK_THEME_PACK;
} else if (activeSelection.source === 'private') {
  const ref = privateThemes.find(t => t.id === activeSelection.id);
  activeThemePack = await ThemeStorageResolver.loadPrivateTheme(ref, session.userId);
} else if (activeSelection.source === 'public') {
  const ref = publicThemes.find(t => t.id === activeSelection.id);
  activeThemePack = await ThemeStorageResolver.loadPublicTheme(ref);
}

// 6. Mount UI with SkipoThemeProvider
return (
  <SkipoThemeProvider initialThemePack={activeThemePack}>
    <AppShell ... />
  </SkipoThemeProvider>
);
```

## 9. Theme Maker Application (`ThemeApp`) Functional Specification

The Theme Maker App (`ThemeApp`) is the tool operators use to design, customize, test, and publish themes. It is **itself** built as a Skipo application and must follow all Skipo laws.

### 9.1 Shell & Navigation Layout

- **`TopToolbar`** (Height: 44px):
  - Left: Brand Logo & Title (`THEME ARCHITECT`).
  - Center: Flat Navigation Tabs (Zero nested tabs permitted):
    1. `Metadata & Setup`: Theme ID, name, semver, mode toggle (`dark` vs `light`), author description.
    2. `Surfaces & Canvas`: Backgrounds, matte blur, gloss gradients, borders, corner radii.
    3. `Palette & Accents`: Primary accent, hover accent, status colors (success, warning, danger, info).
    4. `Typography & Shadows`: Sans/mono font selection, 2.5D tactile shadow offsets and blur.
    5. `Asset Studio`: Monochromatic SVG icon uploader/replacer, 2.5D tactile sprite sheet slicer.
    6. `Systems & Node Graph`: Node canvas styling, socket colors, wire curvature, Monaco editor theme.
    7. `Live Workbench`: Interactive testing room with real Skipo components.
    8. `Export & Publish`: Package validator, private save, zip bundle export, marketplace publisher.
- **`BottomStrip`** (Height: 30px):
  - Left: `StatusLight` (Storage adapter connected), `AutoSaveToggle` (auto-saves draft every 15s).
  - Center: Reactive translucent inspection text smoothly displaying token variable names (`--skipo-*`) and CSS values on hover.
  - Right: `ApiCallIndicator` (storage sync activity) and `SystemMessageDisplay`.
- **Details Panel**:
  - Uses `FloatingDetailsPanel` with 8-way resize handles, draggable header, pin button, and persistent geometry.
  - Used across all tabs for deep token inspection, color ramps, WCAG contrast scoring, and sprite slice coordinates.

### 9.2 Live Workbench Invariant (Law 11: Absolute Zero-Placeholder Rule)

The Live Workbench tab renders an interactive playground with **real, functional `@skipo/ui` and `@skipo/systems` components**.
- **STRICT PROHIBITION**: It MUST NOT render "lorem ipsum", fake telemetry, mock placeholder cards, or dummy text strings.
- **MANDATORY**: It renders genuine Skipo verification fixtures:
  - Real `BaseButton` (variants: `primary`, `secondary`, `danger`, `ghost`).
  - Real `IconOnlyButton` with hover inspection text.
  - Real `CredentialField` linked to an authentic developer portal.
  - Real `NodeGraphCanvas` with genuine data calculation nodes and draggable wires.
  - Real `FloatingDetailsPanel` showing token properties.
  - Real `BottomStrip` and `TopToolbar`.

## 10. Quality Gate & Automated Validation Protocol

Before any theme can be saved to private storage or published to the marketplace, it MUST pass the **Skipo Theme Verification Gate**:

```
THEME VALIDATION GATE
├── 1. Schema Validation (validateThemePack())
│   ├── metadata.id, metadata.mode present and valid
│   └── all mandatory semantic tokens defined
├── 2. AST Token Semantics Check (themeTokenSemanticsRule)
│   └── zero unmapped hardcoded colors in generated styles.css
├── 3. WCAG AA Contrast Audit
│   ├── text.primary against bg.surface (min 4.5:1)
│   ├── text.muted against bg.surface (min 3.0:1)
│   └── accent.fg against accent.primary (min 4.5:1)
├── 4. Zero-Placeholder Check (noPlaceholderDataRule)
│   └── metadata.name and description contain NO prohibited dummy tokens
└── 5. Asset Verification
    ├── all referenced SVGs exist and are valid XML
    └── all referenced sprite sheets load and match atlas dimensions
```
